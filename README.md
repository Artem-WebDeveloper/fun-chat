## About
Fun Chat - real-time мессенджер с полным циклом работы с сообщениями: отправка, доставка, прочтение, редактирование и удаление. Приложение работает поверх `WebSocket` - оба участника диалога получают обновления мгновенно без перезагрузки страницы.

Задача - построить `SPA` без `React`, `Angular` и любых сторонних библиотек. Весь интерфейс генерируется через **TypeScript**, роутинг реализован через hash-изменения, стейт управляется вручную.

Наиболее интересная часть - работа с `WebSocket` как протоколом двусторонней связи: клиент и сервер могут инициировать отправку в любой момент. Это принципиально отличается от привычной модели запрос-ответ и требует другого подхода к управлению состоянием и обновлению UI.

## Goal

Для работы с сокетом намеренно выбрал нативный браузерный `WebSocket` вместо 
`socket.io`. Хотелось разобраться в протоколе без абстракций - понять как 
устроены события, почему нет встроенного механизма запрос-ответ, как 
самостоятельно обрабатывать реконнект и сессию.   
Чат показался идеальным проектом для 
этого - можно обкатать все ключевые аспекты `WebSocket`

## Features

- 🔐 Аутентификация - валидация логина и пароля по разным правилам; вход по кнопке или Enter; защищённые маршруты с редиректом
- 👥 Список пользователей - все зарегистрированные пользователи с индикатором онлайн-статуса и счётчиком непрочитанных сообщений
- 🔍 Поиск - фильтрация пользователей по имени в реальном времени
- 💬 Диалог - полная история переписки, хронологический порядок, скролл к новому сообщению
- ✉️ Статусы сообщений - отправлено → доставлено → прочитано; статус виден только отправителю
- ✏️ Редактирование - изменение текста с пометкой edited, изменение видно обоим участникам
- 🗑️ Удаление - сообщение удаляется у обоих; счётчик непрочитанных корректно уменьшается
- 📍 Разделитель - визуальная граница между прочитанными и непрочитанными сообщениями
- 🔄 Реконнект - при обрыве соединения показывается уведомление и автоматически восстанавливается подключение с реавторизацией без участия пользователя
- 🌐 Роутинг - уникальный URL для каждой страницы; работают кнопки браузера «назад» и «вперёд»

## Challenges
 
>**Нет запрос-ответ - нужен матчинг событий**
 
В REST ты отправил запрос и ждёшь ответ на него. В WebSocket сервер присылает события в общий поток, и непонятно какой ответ на какой запрос. Решил через уникальный `id` в каждом исходящем сообщении - при получении ответа матчу по `id` и типу. Для запросов непрочитанных отдельно веду `unreadCountRequests: Record<string, string>` - маппинг `id запроса → логин пользователя`.
 
>**Чистое и грязное отключение**
 
`socket.onclose` получает `event.wasClean` - и это важное различие. Если `true` - пользователь сам вышел, чистим стор и localStorage. Если `false` - обрыв соединения, запускаем таймер реконнекта и при восстановлении автоматически логиним заново из `sessionStorage`. Без этого различия либо теряешь сессию при случайном обрыве, либо не чистишь её при нормальном выходе.
 
>**Кеш истории в памяти**
 
История сообщений хранится в `messages: Record<string, Message[]>`. При переключении диалога сначала проверяю кеш - если данные есть, рендерю сразу без запроса к серверу. Только при пустом кеше иду за историей. Это убирает мигание при частом переключении между диалогами.
 
>**`deletedMessageIds` как защита от мигания**
 
При удалении сообщения оно добавляется в `Set<string>`. При повторном получении истории (например после реконнекта) удалённые сообщения фильтруются на клиенте до рендера. Без этого они мигали бы при каждом фетче - сначала появлялись, потом исчезали.
 
>**Callback-архитектура вместо глобального стора**
 
Сокет ничего не знает о страницах. Страницы сами подписываются: `socket.onMessage`, `socket.onHistory`, `socket.onDeleteMessage` и так далее. Сокет просто вызывает колбек если он есть. Получилась слабая связность - сокет и страницы независимы, легко тестировать и переиспользовать.

## Setup Dev
 
1. [Запустить сервер локально](#live-demo)
2. Клонировать фронтенд и установить зависимости:
```bash
git clone https://github.com/Artem-WebDeveloper/fun-chat.git
cd fun-chat
npm install
```
 
3. Создать `.env` файл в корне проекта:
```env
VITE_API_URL=localhost:4000
```
 
4. Запустить в режиме разработки:
```bash
npm run dev
```
